# Internationalization

Every user-facing string in the web app comes from a message catalog. English (`en`) is the only locale shipped today; the runtime is built so a second one is a data change, not a refactor.

## Module layout

| File | Role |
|------|------|
| `apps/web/src/i18n/en.ts` | The English catalog — **the only place UI copy lives** |
| `apps/web/src/i18n/index.ts` | Runtime: lookup, interpolation, plurals, locale-aware formatters |

No dependency. The needed surface (lookup + `{placeholder}` interpolation + `Intl.PluralRules` + `Intl.NumberFormat`/`DateTimeFormat`/`RelativeTimeFormat`) is small enough that a hand-rolled module buys full type safety in exchange — same trade as the hand-rolled dashboard SVG.

## Rules

- **A literal string in a template is a bug.** Components call `t("some.key")`; the exception is content the server produced (model ids, account emails, release-note HTML, upstream error text), which is data, not copy.
- **`en` defines the key type.** `MessageKey = keyof typeof en`, so a typo or a key missing from a new locale is a compile error. A key absent from a non-English catalog falls back to English rather than rendering the raw key.
- **Plurals are sibling keys** suffixed with the CLDR category — `models.count_one` / `models.count_other` — selected by `Intl.PluralRules` from the `count` option. Components pass the **base** key and a count: `t("models.count", { count: n })`. The suffixed entries are what the catalog stores but never what a call site names. `MessageKey` is `CatalogKey | PluralBase<CatalogKey>`, where the base union is recovered from the `_one`/`_other` entries themselves — so adding a plural family makes its base callable automatically, and deleting one breaks every call site at compile time. Never build a plural with string concatenation or a ternary; a locale with three or six forms must need only catalog entries.
- **Never format a number or date in a component.** `useI18n().format` exposes `integer`, `compact`, `percent`, `percentValue`, `duration`, `date`, `dateTime`, `relative`, `bucketLabel`, `bucketFull`. They read the active locale per call, so a language switch reformats live. `toLocaleString()` in a component bypasses the app locale and is treated the same as a hardcoded string.
- **Null-safe by contract.** Every formatter renders `—` for `null`/`NaN`, because `request_logs` token fields are nullable ("unreported", not zero — see [database.md](./database.md)).
- `detectLocale()` reads `navigator.languages` and falls back to English; `setLocale()` also sets `document.documentElement.lang`. There is no in-app language switcher while one locale ships — adding one requires a docs update first.

## Copy voice

This is a product surface, not its documentation. The catalog's header comment carries the rules; the load-bearing ones:

- **Say what the user gets, never how it works.** No cache TTLs, poll intervals, "showing cache", "last updated", storage layers, or refresh mechanics anywhere in the UI. Freshness is the app's job to manage, not the user's to read about. (The mechanics themselves are unchanged — see [admin-ui.md](./admin-ui.md) § Data freshness.)
- **Errors name the failure and the next step**, not the layer that threw: "Couldn't load your keys", not "GET /api/keys failed (500)". Upstream error text is still shown verbatim where the user needs it to act.
- Sentence case except proper nouns. No trailing period on labels, buttons, table headers, or menu items; periods only in full sentences.
- Prefer the user's noun over ours: "Providers", not "Account pools"; "Paused", not "benched".

## Adding a locale

1. Copy `en.ts` to `<code>.ts`, translate the values, keep every key.
2. Add the code to `LOCALES` and the catalog to `CATALOGS` in `index.ts`.
3. `pnpm --filter web typecheck` fails on any key you missed.
